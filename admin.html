Sections (the cards on the main page)

One card per section of the lecture notes. After teaching a section, tick Open and press Save on that row — students can then do its quiz. A card only becomes clickable when it is Open and has at least one problem. Label is what students see (2.1), Chapter groups the cards.

Practice problems

Pick a section, then edit any problem. Everything a student sees comes from these fields. Most problems are easier to write in assets/problem_bank.json and loaded with 3 · Import bank.

Edit problem

Extra keys for linear algebra: "tol": 1e-6 (absolute tolerance), "sort": true (sort the answer first — eigenvalues), "check": "np.allclose(A @ got, 3*got)" (a Python expression judged True/False with the answer bound to got; use it when the answer is not unique, e.g. an eigenvector or a basis), "label": "…" (name shown for the test).

Libraries. A problem may import numpy as np, pandas as pd, scipy, matplotlib, sympy and the rest of the standard scientific set — the browser fetches whatever the code imports the first time it is used. Write the expected value of a numpy array or a pandas Series as a plain JSON list; the checker converts the result for you. For a DataFrame, test an expression such as df.values.tolist().

Each test is one of these three shapes:

  • Calls a function \u2014 {"call":"add","args":[2,3],"expected":5}
  • Runs any Python expression after the student's code \u2014 {"expr":"Rectangle(3,4).area()","expected":12}
  • Runs the whole program and checks what it printed \u2014 {"input":["Ann","5"],"expected":["Hello, Ann","10"]}

Problems that use input(). A web page has no keyboard, so input() only works when the test hands it the lines to read. Put them in "input": a list of strings, one per input() call. Use the third shape above for a whole program, or add "input" to a call test for a function that reads. The wording inside input("\u2026") is ignored \u2014 only what the program prints is compared, and trailing spaces and blank lines are forgiven. On the student's scratch pad input() opens a real question box instead.

No function needed? Leave Function / class the tests call empty and use the expr form. An expression can simply be the name of a variable the student was asked to build, which is how you set list-comprehension or slicing questions:

  • Question: \u201cBuild squares \u2014 the squares of 1\u20135 \u2014 with one list comprehension.\u201d
    Tests: [{"expr":"squares","expected":[1,4,9,16,25]}, {"expr":"len(squares)","expected":5}]
  • Question: \u201cSet middle to the 3rd\u20135th items of data.\u201d
    Setup code: data = [10, 20, 30, 40, 50, 60] \u00b7 Tests: [{"expr":"middle","expected":[30,40,50]}]

Import the problem bank

Paste the contents of assets/problem_bank.json (or any file of the same shape: {"weeks":[…], "problems":[…]}, or just a list of problems). Sections are matched by week_no, problems by slug — existing rows are updated, new ones added, nothing is deleted. Run tools/validate_bank.py first: it checks every code problem against a reference solution.
